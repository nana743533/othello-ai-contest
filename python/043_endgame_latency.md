# 終盤完全読みレイテンシ計測メモ

対象実装: [`python/041_endgame.py`](../python/041_endgame.py)  
計測スクリプト: [`python/042_bench_endgame_latency.py`](../python/bench_endgame_latency.py)

## 1. 目的

`041_endgame.py` は空きマス数が `ENDGAME_EMPTY`（既定 12）以下になると、打点評価ではなく **最終石数差の完全読み** に切り替える。

CodinGame の応答制限は次のとおり。

| ターン | 制限時間 |
|--------|----------|
| 初回 | 2000 ms |
| 2ターン目以降 | **150 ms** |

終盤読み切りが 150 ms を超えるとタイムアウト敗北になるため、空きマス閾値と実レイテンシの関係を把握する。

## 2. 計測方法

1. 初期盤面からランダム対戦で空きマスを減らす
2. 空きマス数が指定値になった局面で `choose_endgame_move` を呼ぶ
3. `time.perf_counter()` で所要時間（ms）を測る

中盤の打点合計探索（`search_path`）は計測対象外。終盤ソルバー本体のみを測る。

## 3. 実行方法

リポジトリルート、または `python/` 直下から:

```bash
python3 python/bench_endgame_latency.py
```

オプション例:

```bash
# 空き12だけ、シード0〜9、各局面3回計測
python3 python/bench_endgame_latency.py --empties 12 --seeds 10 --repeats 3

# 空き 12,10,8,6 を比較（既定）
python3 python/bench_endgame_latency.py --empties 12,10,8,6 --seeds 5
```

| 引数 | 既定 | 意味 |
|------|------|------|
| `--empties` | `12,10,8,6` | 計測する空きマス数（カンマ区切り） |
| `--seeds` | `5` | 乱数シード `0 .. N-1` |
| `--repeats` | `1` | 同一局面の計測回数 |

## 4. 計測結果サンプル（2026-07-27）

環境: ローカル macOS / CPython 3。値はマシンにより変動する。

### 4.1 空き12（終盤開始閾値）

| seed | 合法手 | avg_ms |
|------|--------|--------|
| 0 | 4 | 約 2600 |
| 1 | 9 | 約 7500 |
| 2 | 8 | 約 620 |
| 3 | 7 | 約 740 |

おおよそ **0.6〜7.5 秒**。局面依存が大きい。

### 4.2 空きマス数ごとの目安

| 空きマス | レイテンシの目安 | 150ms 制限との関係 |
|----------|------------------|--------------------|
| 12 | 0.6〜7.5 秒 | ほぼ確実に超過 |
| 10 | 30〜250 ms | 局面により超過 |
| 8 | 2〜25 ms | 概ね余裕あり |
| 6 | 1〜2 ms | 十分余裕あり |

## 5. 考察と運用指針

- 現状の純 Python 実装では **`ENDGAME_EMPTY = 12` は CodinGame に不向き**
- 実務的な閾値の目安は **空き 8 前後**（環境・局面で再計測すること）
- 高速化する場合の候補:
  - ビットボード化（C++ 本実装と同様）
  - 手の並び替え強化・置換表
  - 反復深化 + 時間切れで打ち切り

閾値を変える場合は `041_endgame.py` 先頭の定数を変更する。

```python
ENDGAME_EMPTY = 12  # ベンチ結果を見て調整
```
